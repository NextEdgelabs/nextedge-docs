---
title: "Banking glossary"
description: "Shared terms for reviewing books, programmes, cards, lending and operating outcomes."
---

| Term | Meaning in this specification |
| --- | --- |
| Institution/tenant | An isolated institution context; legal entities, programmes and partner duties still need explicit modelling |
| Offering | A permitted bundle of products/modules/channels for an institution |
| Programme | An issuer/lender/sponsor arrangement connecting products, network/processor and financial ownership |
| Product version | Approved, effective-dated terms/eligibility/economics used by an account or instruction |
| CIF/party | Stable verified customer/party identity, not a matching email or synthetic label |
| Mandate | The authority and proof/signature rules for operating an account/product |
| Ledger | Authoritative balanced financial entries and controlled linked corrections |
| Subledger | Detailed product/account obligations reconciling to general ledger |
| Available balance | Amount permitted for use after adopted holds/restrictions/credit rules |
| Authorisation hold | Reservation pending permitted completion/clearing/expiry, not necessarily a final posting |
| Issuer/acquirer | Contracted card issuance and transaction-acceptance roles; not inferred from a software tenant |
| BIN/IIN | Issuer/programme routing identifier with actual network/processor ownership |
| PPI | Prepaid payment instrument governed by its issuer/category and permitted use/funding policy |
| LOS/LMS | Loan origination and post-disbursement servicing systems |
| KFS/MITC | Required disclosure/terms documents applicable to the selected regulated product |
| DPD | Days past due according to the adopted authoritative schedule/policy |
| Maker/checker | Independently authorised initiation and approval duties |
| Clearing/settlement | Transaction obligation exchange and final funds settlement, distinct from authorisation |
| Reconciliation | Evidence that books, instructions, provider outcomes and funds agree with complete sources |
| Business date/EOD/BOD | Institution operating date and controlled end/start-of-day cycles |
| Idempotency | Repeating one original command does not create another economic effect |
| Unknown outcome | The result is unconfirmed; query/reconcile the original reference before any new instruction |
| Reversal/adjustment | Linked corrective financial entry; never deletion of original financial history |
| RPO/RTO | Bank-approved acceptable recovery data-loss window and service-restoration objective |
| HSM/PIN boundary | Approved cryptographic/device handling of sensitive authentication material |
| Commissioned | Identity, policy, interface, security and operational prerequisites accepted for the intended environment |
| Proposed/built/accepted/released | Different statuses; a described feature or passing local test is not bank deployment acceptance |

Use the [decision register](/banking/decisions) to settle institution-specific meanings before implementation.
