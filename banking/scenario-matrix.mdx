---
title: "Scenario and combination coverage"
description: "Risk-based coverage across institutions, products, roles, channels and failure states."
---

“All combinations” must have an explicit boundary. The full Cartesian product is large and includes prohibited combinations. This review defines dimensions, forbidden combinations, mandatory high-risk cases and a process for generating the final test catalogue after policy selection. It does not claim every permutation is implemented or tested.

## Dimensions

| Dimension | Values to select and test |
| --- | --- |
| Institution | Permitted bank category; lending NBFC; deposit-taking NBFC; authorised PPI/card issuer; sponsor/co-brand |
| Product | Savings/current/FD/RD/overdraft; loan variants; debit/prepaid/credit; secured/unsecured/corporate/add-on |
| Party/mandate | Individual; minor/guardian; joint; business/signatory; beneficial owner; programme cardholder |
| Channel | Banking Ops; Customer Web; mobile API; ATM; authenticated contracted interface |
| Authority | Maker; independent checker; viewer; assigned branch; finance/risk; issuer/lender; revoked actor |
| State | Pending/active/restricted/dormant/closed; programme off; product version scheduled/expired |
| Money | Zero/negative invalid; smallest unit; exact limit; above limit; insufficient funds; multi-currency/rounding |
| Time | Quote/hold expiry; cutoff; holiday; month/year/leap day; business versus UTC date |
| Reliability | Duplicate; concurrent; dropped response; outage; reordered event; incomplete file; failover |
| Outcome | Rejected; pending; unknown; confirmed; returned; linked reversal; settled/reconciled |

## Test generation and evidence

For each enabled product, enumerate allowed institution/party/channel combinations, add all applicable S cases and record expected states, book entries, notices and owners. Use pairwise coverage for low-risk display combinations; use exhaustive boundary/concurrency tests for money, permissions, approval and idempotency. Track requirement/feature/journey/scenario IDs to automated test and human UAT evidence.

Actual issuer/network/hardware certification and bank policy acceptance cannot be replaced by mocks or a local browser demo. Document excluded combinations and the reason. Expand this matrix when an offering adds a new legal duty or financial transition.
