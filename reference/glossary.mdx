Use these definitions as a common starting point. Record customer-specific meanings in the project brief.

## Business terms

| Term | Meaning in this handbook |
| --- | --- |
| ERP | Enterprise resource planning: connected workflows and records across business functions |
| POS | Point of sale: the workflow where a sale or order is captured |
| Food and beverages ERP | The business domain connecting POS, procurement, inventory, production, finance, and outlet operations |
| Pharma ERP | The business domain connecting distribution, field-force operations, collections, membership, and loyalty |
| Core banking | Banking modules for customer/account lifecycles, deposits, loans, transactions, controls, and reporting |
| Demand | A request or need that may become an accepted order |
| Fulfillment | The work needed to supply an accepted order |
| Allocation | Reserving or assigning availability against demand under agreed rules |
| Reconciliation | Comparing related records and resolving differences |
| Tenant | A customer or organization boundary used to separate data and permissions |
| Membership | A stockist's enrollment and benefit status within a Pharma ERP program |
| Milestone | A defined achievement evaluated against program rules |
| Entitlement | The recorded right to receive or attempt a benefit |
| Redemption | The authorized use of an allocated reward |
| Ground team | People performing operational work outside the management view |

## Engineering and delivery terms

| Term | Meaning |
| --- | --- |
| Monolith | An application with shared code ownership and coordinated release boundaries |
| Module | A bounded business capability with owned rules and data access |
| API | A defined interface used by clients or other systems |
| CSR | Client-side rendering in the browser |
| SSR | Server-side rendering; in the rendering guide, per-request HTML generation |
| ISR | Incremental static regeneration of cached pages |
| Schema | The expected structure and meaning of stored records |
| Migration | A controlled change to data shape or storage |
| Index | A database structure supporting queries or constraints |
| Replica set | MongoDB deployment with replicated data and failover behavior |
| Sharding | Distribution of database data across shards |
| Transaction | A boundary that commits related database changes together or aborts them |
| Idempotency | Repeating the same request does not repeat its business effect |
| Invariant | A rule that must remain true, including under retries or concurrency |
| UAT | User acceptance testing against the agreed business workflow |
| ADR | Architecture decision record |
| Runbook | Practical instructions for an operational task or recovery |
| SLA | Service-level agreement or target defining expected support outcomes and timing; follow the agreed project terms |
| Recovery | Restoring service or containing critical impact; permanent-fix work may remain |
| Resolution | Correcting and verifying the reported issue |
| Definition of ready | Evidence that work is understood enough to begin |
| Definition of done | Evidence that implementation and verification meet agreed expectations |

For detailed behavior, follow the [engineering guidance](/engineering/architecture) and the official references linked from each technical page.
